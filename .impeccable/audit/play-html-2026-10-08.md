## Detailed findings

### [P2] Shared desktop/tablet home wordmark has a smaller click area

- **Location:** `thoughts/reading-room.css:72`, `.site-brand`; used by `play.html:50`. The phone minimum-height rule is at `thoughts/reading-room.css:425`.
- **Category:** Responsive design / pointer accessibility.
- **Evidence:** The browser measured approximately **143.48 × 28 CSS pixels** at widths of 1346, 875, and 768px. At 390 and 320px, the same control is 44px high. The neighboring Start link and project actions have at least 44px-high targets.
- **Impact:** Touchscreen tablet/laptop users have less vertical room to activate the home wordmark. The larger Start link offers the same destination.
- **Standard:** This is a 44px comfort-target inconsistency, not a verified WCAG 2.2 AA failure. The target exceeds the 24px minimum; equivalent controls also matter to target-size exceptions.
- **Recommendation:** If the user revisits the shared header, expand the hit area without changing the wordmark baseline, visual size, or header geometry, and inspect sibling reading pages. This pass intentionally preserves the established header preference.
- **Suggested command:** `/impeccable adapt` on the shared reading header, followed by `/impeccable polish`.
